# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

> Общайся с пользователем на русском. Проект самодостаточен; родительские инструкции не требуются.

## Переносимая сборка и новый процесс

Главный гайд — `README.md`, Windows — `docs/WINDOWS.md`. Все базы находятся внутри
этого проекта. Для сайта с подбором референсов и насыщенной анимацией используй
`.agents/skills/site-from-ref-motion/SKILL.md` (Claude: `/site-from-ref-motion`).
Он расширяет исходный процесс: поиск по всей базе, просмотр видео через FFmpeg,
полная прокрутка Playwright и QA движения. Направления — варианты одного паттерна.
Каталог анимаций: `/motion_reference/`. В публичном репозитории нет Refero-медиа
и компонентов React Bits; выбранное скачивается `scripts/fetch_assets.py`.
Локальная полная копия остаётся на диске.
На Windows используй `py -3` вместо `python3`, либо `setup-windows.cmd`/`start-windows.cmd`.
Старые примеры ниже с `curl`, `lsof`, симлинками и shell-хуком относятся к macOS;
они не нужны для основного процесса. Новый запускатель не требует Stop-хука.

## Что это

Две связанные вещи в одной рабочей папке:
1. **Галерея-референс** — офлайн-копия видео-галереи **styles.refero.design**: метаданные всех
   сайтов + локально скачанные превью-видео и скриншоты, собранные в одну самодостаточную
   HTML-страницу (`site-copy/index.html`). Каждая карточка ведёт на оригинальный сайт.
2. **Мои сайты** — рабочая папка `generated-sites/`, где Claude по мотивам референсов делает
   собственные лендинги. Отдельная вкладка-галерея (`generated-sites/index.html`) с категориями
   и живыми превью.
3. **Секции** — вкладка `sections/index.html`: для каждого проанализированного референса — анатомия
   страницы (упорядоченный список секций: тип + заголовок). Три вкладки связаны верхней навигацией
   «Референсы | Мои сайты | Секции».

Основные скрипты — Python 3.9+ (stdlib). Для браузера и видео нужны Node.js 22+,
Playwright и ffmpeg-static: зависимости закреплены в `package-lock.json`, установка `npm ci`.
`package.json` и lockfile хранятся в Git; `node_modules/` исключён. Проверки: `npm test`.

## Конвейер (как всё связано)

**Анимации:** подбираются напрямую из локального `motion_reference/`
под концепцию сайта. Изучи исходник и демо выбранного эффекта, адаптируй к стеку сайта
и сохрани лицензии. Проверь работу в браузере, reduced motion и читаемость без JS.

```
API refero (пагинация)  →  all_styles.json  →  download.py  →  site-copy/media/{videos,thumbs}/<id>.{mp4,jpg}
                                            ↘  build_gallery.py ──► site-copy/index.html          (вкладка «Референсы»)
                          classification.json ↗          ↖ taxonomy.py (CAT_ORDER/TAG_ORDER) ↗
                                                                    build_generated.py ──► generated-sites/index.html  (вкладка «Мои сайты»)
                          generated-sites/projects.json ↗   +  generated-sites/<slug>/index.html (сами лендинги)
                          generated-sites/post_template.txt ↗  (оффер + {hook} из projects.json → чип «Пост»)

оригинальные сайты ─ analyze_sections.js (Playwright) ─► sections.json ─ build_sections.py ─► sections/index.html (вкладка «Секции»)
```

1. **Сбор метаданных** — публичный JSON-API галереи: `GET https://styles.refero.design/api/styles?sort=trending&page=N`.
   Ответ — объект `{styles, nextCursor, nextPage}`, 20 карточек на страницу, пагинация по `nextPage` (~65 страниц ≈ 1288 сайтов). `api_p1.json` — образец одной сырой страницы. Эндпоинт был найден реверсом JS-чанков (`chunks/`); `robots.txt` запрещает `/api/` ботам — качалось для личного офлайн-просмотра.
2. **`all_styles.json`** — единый источник правды (1288 объектов). Ключевые поля карточки: `id`, `url` (оригинальный сайт), `siteName`, `previewVideoUrl` (1200×750), `previewVideoPosterUrl`, `screenshotUrl`/`thumbnailUrl`, `colorScheme`, `colors`, `fonts`. Оба последующих скрипта читают **только** этот файл.
3. **`download.py`** → скачивает видео/постеры. **Резюмируемый и идемпотентный**: пропускает уже скачанные непустые файлы (`need()`), пишет во временный `.part` и атомарно `os.replace`. 16 потоков, таймаут 120с, 4 ретрая с backoff. CDN троттлит ~1 МБ/с. Неудачи → `download_failed.json`.
4. **`classification.json`** — ручная (Claude) классификация всех 1288 карточек: `{"<id>": {"cat": "<категория>", "tags": ["<тег стиля>", …]}}`. Категория одна из 18 (SaaS, финтех, e-commerce, портфолио…), тегов стиля 1–3 из 16 (дарк, минимализм, editorial-типографика…) — канонические списки и порядок дропдаунов заданы в `CAT_ORDER`/`TAG_ORDER` внутри **`taxonomy.py`** (общий модуль обеих галерей). Классифицировано по `siteName`/домену/`northStar` (+ скриншоты для спорных). Файл опционален: без него галерея соберётся без фильтров категорий.
5. **`build_gallery.py`** → генерирует `site-copy/index.html` из `all_styles.json` + `classification.json` (таксономию берёт из `taxonomy.py`). Все данные **встраиваются в страницу как один JSON** (заглушки `__DATA__`/`__CATS__`/`__TAGS__`/`__N_TOTAL__`/`__N_VIDEO__` в HTML-шаблоне) — внешних запросов на чтение данных нет. Фронтенд: верхняя навигация «Референсы | Мои сайты», поиск (понимает и категории/теги), дропдауны «Категория»/«Стиль» со счётчиками, фильтры «Все/С видео/Без видео/Избранное», кнопка **«Бриф ⧉»** на карточке (копирует в буфер готовый промпт для ИИ-агента: категория + `northStar` + палитра + шрифты + ссылки; `navigator.clipboard` с fallback на `execCommand`), ленивая загрузка картинок через IntersectionObserver, видео по ховеру (десктоп) / тапу (моб.). Карточки сортируются: сначала с видео, потом по имени.

`site-copy/` — это итоговый артефакт-доставка (см. его собственный README). `media/` весит ~1.8 ГБ (бинарь, в git не класть).

## Вкладка «Мои сайты» (генерация лендингов)

Рабочий цикл: пользователь выбирает референсы (описывает тему словами / кидает ссылки / просит
подобрать самому) → Claude анализирует их и создаёт лендинг. **Формат сайта — одностраничный
самодостаточный `index.html`** (inline CSS/JS, шрифты через Google Fonts), как текущие примеры.

**Скиллы конвейера:** `/site-from-ref` (сайт по дизайн-системе) → `/site-slop` (шаблонный
ИИ-клон этого сайта, собирается ТОЛЬКО по скриншотам, в код лендинга не заглядывая) →
`/site-comparison` (сравнительное видео). `/site-end` прогоняет все три подряд за один заход.

**Где лежат сравнительные ролики:** финалы сгруппированы по дате генерации —
`generated-sites/_videos/<YYYY-MM-DD>/<slug>.mp4` (имя файла = slug сайта, дата = день, когда
собирался ролик; при генерации пачками так они не сваливаются одной кучей за всё время). В папке
сайта на своё видео стоит относительный симлинк `<slug>/comparison/comparison-final.mp4` →
`../../_videos/<дата>/<slug>.mp4`, поэтому старый путь и чип «Видео» в галерее работают как раньше:
`os.path.isfile`, `serve.py` и `file://` проходят симлинк насквозь. Раскладку делает сам
`make_comparison.js` (дата берётся автоматически, переопределяется флагом `--date-dir`), вручную
ничего переносить не нужно; в папке сайта остаются только промежуточные `*-scroll.mp4` и
`ai-version.html`. Удалять ролик отдельно не надо — `delete_site.py` находит файл в любой из
датированных подпапок (и по старому плоскому пути) и снимает его вместе с папкой сайта.

**Методика сборки по референсу (важно!):** подробный чек-лист — в скилле
`.claude/skills/site-from-ref/SKILL.md`, здесь короткая версия.

1. **Выгрузка страницы стиля (фундамент)** — `node .claude/skills/site-from-ref/fetch_style.js <id>`
   забирает все четыре вкладки: `tokens.css` (`:root` — вставлять в сайт дословно), `design.md`
   (DESIGN.md Extended целиком: роли токенов, компоненты, Do/Don't), `tokens.json`
   (`$description` по каждому токену), `tailwind.css` (`@theme`). Первые три лежат в HTML,
   четвёртую скрипт снимает кликом по вкладке в Chromium.
2. **WebFetch — в дополнение** — `WebFetch styles.refero.design/style/<id>` даёт быстрый обзор,
   но это пересказ страницы маленькой моделью: числа и формулировки берём из файлов п.1.
   Страница стиля — не `/api/`, robots её не блокирует.
3. **Анатомия секций** — посмотреть запись референса в `sections.json` (вкладка «Секции») — из каких
   блоков собран сайт. Нет записи → `node analyze_sections.js <id>` (Playwright рендерит и достаёт секции).
4. **Реальный вид** — `Read site-copy/media/thumbs/<id>.jpg` (хиро). **Скриншот главнее прозы:**
   правило вида «намеренно обрезай/переполняй» сверять с пикселями до вёрстки. Кадры из видео
   извлекай через `node scripts/storyboard.cjs <video> <outDir>`.
5. Шрифты ОБЯЗАНЫ иметь кириллицу (двуязычность RU/EN), никакого шаблонного «AI-look».
6. **Визуальный QA** — `node .claude/skills/site-from-ref/shot.js <slug>` снимает десктоп (1440×900)
   и RU-версию, печатает overflow-x и ошибки страницы; кадры смотреть глазами. **Мобильную
   версию не делаем и не проверяем** — сайты галереи верстаются только под десктоп.

Порядок добавления нового сайта:
1. Создать `generated-sites/<slug>/index.html` — сам лендинг.
2. Добавить запись в **`generated-sites/projects.json`** (единственный источник правды галереи «Мои сайты»):
   `slug`, `name`, `cat` (из `CAT_ORDER`!), `cs` (`dark`/`light`), `tagline`, `cluster`, `desc`, `date`,
   `post` (крючок поста, см. ниже), `refs: [{name, id, url}]` — сайты-референсы
   (`id` = ключ карточки в `all_styles.json`).
3. `python3 build_generated.py` — пересобрать `generated-sites/index.html`.

**`build_generated.py`** генерирует галерею «Мои сайты»: карточки с **живым превью** (iframe с
`<slug>/index.html`, масштабируется через ResizeObserver), фильтр по категориям и по метке, поиск,
сортировка (новые/старые/по метке/А-Я — двигает CSS-свойством `order`, а не переносом узлов, иначе
iframe’ы перезагружаются). Чипы в строке «На основе:» ведут на **страницу дизайн-системы в Refero**
(`styles.refero.design/style/<id>`) — источник, из которого собран сайт, а не на сайт-оригинал;
поэтому `id` в `refs` обязателен. Категории берёт из `taxonomy.py`. Схема и подробный гайд —
в `generated-sites/README.md`.

### Текст поста для X — чип «Пост» на карточке

Пользователь публикует сравнительные ролики в X с одним и тем же оффером, а первые строки пишет
под конкретный сайт. Поэтому текст собирается из двух частей:

- **`post`** в записи `projects.json` — только уникальный крючок, **две строки через `\n`,
  по-английски**: первая — что за продукт (конкретно, с цифрой из темы), вторая — контраст
  «что сделал бы LLM-дефолт ↔ что делает эта дизайн-система» её настоящими приметами
  (палитра, материал, типографика). Общих слов про «AI slop» и повторов соседних записей избегать.
- **`generated-sites/post_template.txt`** — общий хвост-оффер с плейсхолдером `{hook}`
  (цена, число клиентов, приглашение в DM). Один файл на все сайты: правка + `build_generated.py`
  обновляют текст на всех карточках сразу.

Готовый текст вшивается в карточку при сборке: чип **«Пост»** рядом с «ИИ-слоп»/«Видео» раскрывает
панель с текстом, кнопка «Копировать ⧉» кладёт его в буфер. Записи без `post` дают серый пунктирный
чип и находятся в поиске по «без поста». **Новый сайт без `post` не считается доделанным.**

### Метки светофора — как я их учитываю (ОБЯЗАТЕЛЬНО читать перед генерацией сайта)

Пользователь оценивает **мои готовые сайты** четырьмя точками на карточке галереи; оценки лежат в
**`generated-sites/ratings.json`**: `{"<slug>": {"rating": "star|green|yellow|red", "note": "…", "posted": true|false, "ts": "…"}}`.
Перед выбором темы нового сайта файл нужно прочитать и применить:

- ⭐ **star — топ-образец.** Сильнее «зелёной»: личный фаворит, эту тему и подачу повторить
  в первую очередь. Смотри `note` — там сказано, чем именно сайт хорош.
- 🟢 **green — образец.** Такие темы и такую подачу делать ещё: держись их плотности, тона,
  уровня детализации, приёмов. Смотри `note` — там сказано, чем именно сайт хорош.
- 🔴 **red — избегать ТЕМУ.** Не повторять тему этого сайта и близкие к ней (тема = `tagline` +
  `cluster` + `cat` его записи в `projects.json`, плюс `note`). **Референс в бан не идёт:**
  дизайн-система из `refs` остаётся полностью доступной и её можно брать под другую тему —
  запрещена именно тема и её подача, а не источник вёрстки.
- 🟡 **yellow — нейтрально.** Не образец, но и не запрет.

Отдельно от цветной метки — поле `posted` и чип **«🐦 Класс»** на карточке: ручная отметка
«этот сайт я уже запостил в X/Twitter», для памяти пользователя. К оценке отношения не имеет —
ставится и снимается независимо, можно и без рейтинга.

Метки пишутся только когда галерея открыта через `python3 serve.py` (страница шлёт `POST /api/ratings`).
По `file://` они осядут в localStorage браузера и до `ratings.json` не доедут — в шапке про это
предупреждает жёлтая строка. Записи для удалённых сайтов вычищает `delete_site.py`.

### Сервер всегда должен быть поднят

**Правило пользователя:** после любого изменения и любой выполненной задачи галерея должна быть
доступна по `http://localhost:8080/generated-sites/` — не заставляй его запускать сервер руками.

Исполняет это **Stop-хук** в `.claude/settings.local.json`: по завершении каждого ответа он смотрит,
слушает ли кто-то порт 8080, и если нет — поднимает `python3 -u serve.py` в фоне (лог —
`~/.claude/serve-8080.log`). Хук идемпотентен: пока сервер жив, второй экземпляр не стартует.
Перезапускать сервер после правки файлов не нужно — он отдаёт статику с `Cache-Control: no-store`,
так что пересобранная галерея видна по F5. Если сервер всё же понадобилось остановить —
`kill $(lsof -ti:8080)`, но он поднимется снова в конце следующего ответа.

### Доступ с телефона

Галерею видно с телефона через **Tailscale** (клиент должен быть включён на обоих устройствах,
аккаунт один). Рабочие адреса, все ведут в один и тот же `serve.py`, метки светофора пишутся в файл:

- `http://100.88.98.57:8080/generated-sites/` — по Tailscale-IP мака, работает всегда;
- `http://macbook-air.tail040dff.ts.net/generated-sites/` — через `tailscale serve` (без порта),
  требует MagicDNS на телефоне;
- `http://192.168.0.194:8080/generated-sites/` — только пока телефон в домашнем Wi-Fi
  (адрес по DHCP, проверять `ipconfig getifaddr en0`; на 13.08.2026 был `.194`, до этого `.108`).

Раздачу по имени включает `tailscale serve --bg --http=80 8080` (настроена постоянно, переживает
перезагрузку; снять — `tailscale serve --http=80 off`). Только HTTP: выпуск TLS-сертификата
(`tailscale cert`) на этой машине зависает, поэтому 443 отключён — внутри тайлнета трафик и так
шифруется WireGuard'ом. Побочный эффект non-secure context: кнопка «Бриф ⧉» падает на
`execCommand`-фолбэк вместо `navigator.clipboard`.

Мак не должен спать, иначе адреса отвалятся: `caffeinate -s`.

## Команды

```bash
python3 download.py            # докачать медиа (только недостающее); зависит от all_styles.json
python3 build_gallery.py       # пересобрать site-copy/index.html (вкладка «Референсы»)
python3 build_generated.py     # пересобрать generated-sites/index.html (вкладка «Мои сайты») из projects.json
python3 serve.py [порт]        # сервер галереи (по умолчанию 8080) — раздаёт репозиторий И
                               #   сохраняет метки светофора в generated-sites/ratings.json.
                               #   Открывать метки надо ТОЛЬКО так: http://localhost:8080/generated-sites/
                               #   Слушает 0.0.0.0 — видно с телефона (см. «Доступ с телефона»);
                               #   HOST=127.0.0.1 python3 serve.py — только локально
python3 delete_site.py <slug>  # удалить сайт целиком: папку (лендинг + ИИ-слоп + скроллы),
                               #   ролик _videos/<дата>/<slug>.mp4, запись в projects.json, метку в
                               #   ratings.json и пересобрать галерею. Спрашивает подтверждение;
                               #   --dry покажет, что уйдёт, --yes без вопросов
node analyze_sections.js [id…] # разобрать секции референса(ов) через Playwright → sections.json
                               #   без аргументов — все refs из projects.json; --all — все 1288 (долго!)
python3 build_sections.py      # пересобрать sections/index.html (вкладка «Секции») из sections.json
```

Playwright ставится один раз: `npm i playwright && npx playwright install chromium`.

Открыть результат: двойной клик по `site-copy/index.html` (или `generated-sites/`, `sections/`).
Между вкладками — верхняя навигация. Но **если собираешься ставить метки — открывай через
`python3 serve.py`** (`http://localhost:8080/generated-sites/`): только там они попадают в файл.
Заодно это лечит капризы видео/превью по `file://` в Chrome. Голый `python3 -m http.server 8080`
из корня тоже раздаст все три вкладки, но `/api/ratings` у него нет — метки уйдут в localStorage.

## Обновление галереи

Заново спарсить метаданные (пагинация API по `nextPage`, сохранить в `all_styles.json`) →
`python3 download.py` → `python3 build_gallery.py`. Скрипта-сборщика метаданных в репозитории
нет — `api_p1.json`/`home_map.json`/`*.html`/`rsc_*.txt`/`chunks/` это артефакты реверс-инжиниринга
сайта, оставленные для справки, а не часть автоматического конвейера.

## Соглашения

- `id` карточки — сквозной ключ: имена файлов медиа (`<id>.mp4`/`<id>.jpg`), пути в `index.html`
  (`vpath`/`tpath`), ключи `classification.json` и ссылка на страницу стиля (`https://styles.refero.design/style/<id>`) строятся из него. При смене схемы хранения её надо менять синхронно в `download.py` и в `build_gallery.py`.
- Все скрипты резолвят пути от своего расположения (`ROOT = dirname(abspath(__file__))`) — запускать можно из любой директории.
- Метки в `classification.json` и `generated-sites/projects.json` — только из `CAT_ORDER`/`TAG_ORDER` (**`taxonomy.py`**, общий для обеих галерей): новая метка, которой нет в этих списках, не попадёт в дропдауны. При докачке новых сайтов их надо доклассифицировать (карточки без записи в `classification.json` рендерятся без бейджа и не находятся фильтрами категорий).
- Кросс-ссылки между вкладками относительные (`../generated-sites/index.html` ↔ `../site-copy/index.html`); при переносе папок держать структуру `site-copy/` и `generated-sites/` рядом.

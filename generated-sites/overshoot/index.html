The screen inside the screen

A fictional interface has one job: to be read in under two seconds by an audience that is not looking at it. That is a harder constraint than any product UI, and it is the only constraint we optimise for.

Everything we ship is built as a working instrument first — real data structures, real states, real failure modes — and only then dressed for camera. It is why our panels hold up in close-up and why a director can call for a new readout on set without a rebuild.

How a job runs

→ 01

Read the script

We start from the scene, not the moodboard. What must the audience understand, and in how many frames.

→ 02

Build the instrument

States, data and failure modes first. If the panel cannot show an error, it is not finished.

→ 03

Dress for camera

Contrast, scale and motion tuned to the lens and the distance it will actually be shot from.

→ 04

Hand over the keys

You get the source project and a short manual, so the next change does not require us.

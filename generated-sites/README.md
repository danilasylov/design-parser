# Мои сайты — рабочая папка

Здесь живут **сгенерированные лендинги** — сайты, которые Claude делает по мотивам
референсов из галереи (`../site-copy/index.html`). Каждый сайт — самодостаточный
`index.html` в своей папке; галерея `index.html` этой папки собирает их все на одну
страницу с категориями и ссылками на референсы.

Открыть галерею «Мои сайты»: двойной клик по `generated-sites/index.html`
(или из галереи-референса — кнопка **«Мои сайты →»** сверху). Между двумя вкладками
переключает верхняя навигация «Референсы | Мои сайты».

**Хочешь ставить метки — открывай через сервер:** `python3 serve.py` в корне репозитория,
дальше `http://localhost:8080/generated-sites/`. По `file://` метки останутся в браузере.

## Как устроено

```
projects.json  ──► build_generated.py ──► generated-sites/index.html (вкладка «Мои сайты»)
   ▲               ▲                          │  живые превью (iframe), фильтры, сортировка
   │               │ ratings.json ◄──── POST /api/ratings ◄─── клик по метке (serve.py)
   │ одна запись = один сайт                  ▼
   └──────────── <slug>/index.html (сам лендинг, self-contained)
```

- **`projects.json`** — источник правды: список сайтов. Ничего, кроме него и `ratings.json`,
  галерея не читает.
- **`ratings.json`** — метки светофора (см. ниже). Отдельный файл: пересборка галереи его не трогает.
- **`build_generated.py`** (в корне репозитория) — пересобирает `index.html` из `projects.json`.
  Категории берёт из `../taxonomy.py` (общие с галереей-референсом).
- **`<slug>/index.html`** — сам сайт. Один файл, inline CSS/JS, шрифты через Google Fonts.
  Открывается двойным кликом, ничего собирать не нужно.

## Метки светофора (`ratings.json`)

Три точки в правом верхнем углу превью — оценка **готового сайта**. Повторный клик по горящей
метке её снимает. Под карточкой оценённого сайта появляется поле заметки — одна строка о том,
чем сайт хорош или что не так с темой; она сохраняется вместе с меткой.

| метка | смысл | что делает Claude |
|---|---|---|
| 🟢 зелёная | хорошо | делает ещё такие темы и такую подачу — это образец |
| 🟡 жёлтая | средне | ничего особенного: не образец, но и не запрет |
| 🔴 красная | плохо | **избегает ТЕМУ** этого сайта и близкие к ней |

**Красная метка не банит референс.** Дизайн-система из строки «На основе:» остаётся доступной и
может пойти в другой сайт — обходить надо именно тему и её подачу (`tagline` + `cluster` + `cat`
записи плюс текст заметки).

Формат файла — ключ по `slug` из `projects.json`:

```json
{ "windfall": { "rating": "red", "note": "тема слишком заезженная", "ts": "2026-08-10T22:13:06" } }
```

Файл можно править руками. Сервер отвергает слаги, которых нет в `projects.json`, и метки кроме
`green`/`yellow`/`red`; `delete_site.py` вычищает метку удалённого сайта.

Сверху страницы видно, куда уходят клики: зелёное «метки → ratings.json» — сервер пишет файл,
жёлтое «метки только в браузере» — страница открыта без `serve.py`, и метки лежат в localStorage
(тогда открой галерею через сервер и проставь заново).

## Фильтры и сортировка

- **Поиск** — по названию, категории, тэглайну, кластеру, референсам, словам «без слопа» / «без видео».
- **Категория** — дропдаун из `CAT_ORDER`.
- **Метка** — переключатель «Все / 🟢 / 🟡 / 🔴 / без метки» со счётчиками.
- **Сортировка** — «Сначала новые» (по умолчанию), «Сначала старые», «Метка: зелёные → красные»,
  «Метка: красные → зелёные» (неоценённые всегда в хвосте), «Название А-Я».

## Рабочий цикл (как заказать сайт)

1. В галерее-референсе (`../site-copy/index.html`) находишь понравившиеся сайты.
2. Даёшь Claude задание одним из способов:
   - **описываешь тему** словами («лендинг для крипто-кошелька, тёмный премиум») — Claude сам подберёт референсы из галереи;
   - **кидаешь ссылки** на конкретные сайты, которые зацепили;
   - **просишь выбрать референсы самому** под нишу.
3. Claude анализирует референсы, создаёт `generated-sites/<slug>/index.html`,
   добавляет запись в `projects.json` и пересобирает галерею.
4. Новый сайт появляется во вкладке «Мои сайты» с живым превью и ссылками на референсы.

## Соглашения по сайтам

- **Двуязычность (RU/EN).** Каждый сайт — с переключателем **RU / EN** в шапке. Обе версии
  текста лежат в одной странице: переводимым узлам — `data-i18n="ключ"`, переводы — в JS-словаре
  `I18N` внизу файла (значение может содержать HTML, подставляется через `innerHTML`); `apply(lang)`
  ставит `html[data-lang]`; дефолт всегда `en`, без автоопределения `navigator.language`.
  Не переводить имена собственные, e-mail, адреса, координаты, числа. **Эталон — `datum/index.html`.**
- **Никакого шаблонного «AI-look».** Сдержанность, один акцент, характерная типографика, кастомные
  SVG-иконки (не эмодзи), конкретный концепт. Не переиспользовать одну раскладку/компонент между сайтами.

## Формат записи в `projects.json`

```json
{
  "slug": "meridian",                       // папка сайта = generated-sites/meridian/
  "name": "Meridian",                       // заголовок карточки
  "cat": "финтех и банки",                  // категория из taxonomy.py (CAT_ORDER)
  "cs": "dark",                             // "dark" | "light" — бейдж схемы
  "tagline": "AI-терминал для инвесторов",  // короткая суть
  "cluster": "тёмное институциональное",    // направление дизайна (необязательно)
  "desc": "Серифы на почти-чёрном, ...",    // 1–2 предложения про дизайн
  "date": "2026-07-11",                     // день; порядок карточек — новые сверху,
                                            // сайты одного дня разводит время создания
                                            // <slug>/index.html (место строки в JSON не важно)
  "post": "An AI terminal…\nAI would…",     // крючок поста для X: две строки через \n
  "refs": [                                 // сайты-референсы (ведут на оригиналы)
    { "name": "Altitude", "id": "0e971626-…", "url": "https://www.altitude.so" }
  ]
}
```

`cat` должна быть из `CAT_ORDER` в `taxonomy.py`, иначе карточка не попадёт в фильтр
категорий. `id` референса — ключ карточки в `all_styles.json`; **чип «На основе:» на карточке
ведёт именно на `https://styles.refero.design/style/<id>`** — на дизайн-систему, по которой
собран сайт, поэтому `id` обязателен. `url` (сайт-оригинал) хранится для справки.

## Текст поста (чип «Пост» на карточке)

Пост для X к сравнительному ролику собирается из двух частей:

- **`post` в записи сайта** — только уникальный крючок: первая строка про сам продукт
  (конкретно, с цифрой), вторая — контраст «LLM-дефолт ↔ эта дизайн-система» её настоящими
  приметами. По-английски, две строки через `\n`.
- **`post_template.txt`** рядом с этим README — общий хвост (оффер, цена, приглашение в DM)
  с плейсхолдером `{hook}`. Один файл на все сайты: поменял цену или число клиентов —
  `python3 build_generated.py`, и текст обновился на всех карточках.

Готовый текст вшивается в карточку при сборке; чип «Пост» его раскрывает, кнопка «Копировать ⧉»
кладёт в буфер. Нет `post` — чип серый пунктирный, в поиске такие сайты находятся по «без поста».

## Как собирается сайт (действующий порядок)

Каждый сайт в этой папке собран по одному и тому же конвейеру — не «по мотивам скриншота»,
а по опубликованной дизайн-системе конкретного референса:

1. **Дизайн-система.** У страницы стиля четыре вкладки, все выгружаются скриптом
   `node .claude/skills/site-from-ref/fetch_style.js <id>`: `tokens.css` (`:root` — вставляем в
   сайт дословно), `design.md` (DESIGN.md Extended целиком — роли токенов, компоненты, Do/Don't),
   `tokens.json` (`$description` по каждому токену), `tailwind.css`. WebFetch страницы — только
   как быстрый обзор: он отдаёт пересказ, а не дословный текст.
   Верстаем строго по этим значениям, включая запреты (у Wealthsimple — ни одного акцентного цвета,
   у Composer — единственная чёрная заполненная кнопка, у Foundry — оранжевый только обводкой).
2. **Анатомия секций.** Запись референса в `../sections.json` (вкладка «Секции») — из каких блоков
   и в каком порядке собрана страница. Нет записи → `node ../analyze_sections.js <id>`.
3. **Реальный вид.** `../site-copy/media/thumbs/<id>.jpg` — хиро референса. Скриншот главнее прозы:
   правило вида «намеренно обрезай/переполняй» сверяем с пикселями до вёрстки (на `stanza` проза
   требовала обрезать display-слова, а на живом Iad-lab слово занимает ровно ширину экрана).
4. **Шрифты.** Оригинальные гарнитуры почти всегда без кириллицы, поэтому берём стойку из раздела
   fallback самой системы (Tiempos → Source Serif 4, Neue Montreal → Manrope, SuisseIntl → Inter,
   Libre Baskerville → Source Serif 4 для кириллических глифов). Двуязычность RU/EN обязательна.
5. **Анимации.** Выбрать эффекты напрямую из соседнего `motion-animation/motion_reference`,
   изучить исходник и демо, адаптировать к HTML/CSS/JS и сохранить лицензии рядом с сайтом.
6. **Проверка.** Только десктоп 1440×900 согласно `CLAUDE.md`: кадры EN/RU, отсутствие
   ошибок и горизонтального переполнения. Отдельно проверить изменение анимации во
   времени, триггеры, порядок, reduced motion, паузу циклов и текст без JS.

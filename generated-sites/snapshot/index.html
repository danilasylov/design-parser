A branch is a database, not a ticket

No request to the DBA, no restore window, no shared staging box that four teams keep breaking. The engineer runs one command and gets a DSN that behaves exactly like production — same row counts, same indexes, same query plans, different people.

  • 01Same shape. Row counts, index bloat and table statistics are carried over, so a plan that goes sequential here goes sequential there.
  • 02Same keys. Masking is deterministic per rule set: the same customer keeps the same fake email across eleven tables, and every foreign key still resolves.
  • 03Not the same people. Nothing that identifies a person leaves the vault. The branch is built from the masked image, never from the primary.

Masking

Seven rules, written in the repo, reviewed in the pull request

Rules live in masking.toml next to the migrations. A new column without a rule fails the build — the default is refusal, not passthrough.

Free-text columns are the hard ones. redact_spans runs a span classifier over the text and replaces names, account numbers and addresses in place — the sentence keeps its length and language, which is why parsers downstream keep working.

Copy-on-write

The branch shares blocks with the base image until it changes them. A four-terabyte database and a four-gigabyte one take the same ninety seconds.

Rules in review

Masking is a file in the repository with an owner and a diff. Adding a column that stores a phone number without saying so breaks CI.

Leak test on every restore

Two thousand sampled rows go through fourteen detectors — card numbers, passport patterns, e-mail shapes, Russian phone masks. One hit and the branch is destroyed instead of handed over.

Branches expire

Seventy-two hours by default, and the TTL is printed in the connection string. Nobody discovers a two-year-old copy of the customer table on a laptop.

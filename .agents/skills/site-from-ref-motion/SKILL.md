# Сайт по референсам и паттернам движения

Работай из корня Design Parser (рядом `all_styles.json`). Все базы находятся внутри проекта:
`motion_reference/` — анимации, `site-copy/` — сайты, `generated-sites/` — результаты.
Никаких зависимостей от соседних папок, абсолютных путей автора или macOS-команд.
Windows: `py -3`; macOS/Linux: `python3`; `node` одинаков на всех ОС.

Прочитай `CLAUDE.md`, `generated-sites/README.md` и
`.claude/skills/site-from-ref/SKILL.md`. Применяй дизайн-токены, приоритет пикселей,
кириллицу, EN по умолчанию, RU-переключатель, формат сайта и регистрацию в галерее
из исходного процесса. Этот скилл заменяет его этапы выбора референса, просмотра
видео и добавления анимаций. Повторное использование референса разрешено, если он
лучше подходит явному запросу пользователя. Новую тему не подменяй свободной категорией.
По умолчанию сохраняй принятую в проекте десктопную вёрстку; иной размер — по запросу.

## Подбор из всей базы

1. Прочитай бриф и оценки `generated-sites/ratings.json`: красная метка запрещает
   повторять тему, а не дизайн-систему; star/green дают образцы подачи. Явный запрос
   пользователя важнее предпочтений прежней галереи.
2. Прогони запрос и его смысловые варианты через поиск:

   ```text
   python3 scripts/select_references.py sites "тема аудитория настроение" --out .cache/brief/sites.json
   ```

   Скрипт ранжирует ВСЕ 1288 записей, включая категории, стилевые теги и заголовки
   секций. Это лексический отбор с RU/EN-расширениями, не доказательство сходства.
   Если подходящих кандидатов мало, переформулируй запрос, переведи ключевые слова
   на английский или выведи всю категорию с `--category` и `--limit 0`.
   Явные ссылки/ID пользователя добавляй независимо от рейтинга скрипта.
3. Посмотри постеры и анатомию примерно 8–12 кандидатов. Для 3–5 наиболее подходящих
   изучи видео; число увеличивай, когда бриф требует. Выбери одну основную систему
   и дополнительные референсы для конкретных секций/взаимодействий. Зафиксируй
   причины выбора и отказа в `.cache/<slug>/selection.md`.

## Весь ролик и вся страница без тысяч кадров

FFmpeg обрабатывает запись, а сайт открывает и прокручивает Playwright.
Установить зависимости: `python3 scripts/project.py setup` (Windows: `py -3`).

Для выбранных ID скачай только нужные файлы, затем извлеки обзор:

```text
python3 scripts/fetch_assets.py --sites <id1> <id2>
node scripts/storyboard.cjs site-copy/media/videos/<id1>.mp4 .cache/<slug>/refs/<id1>
```

Открой `overview.jpg`: 12 равномерных кадров по всей длительности видео за один
проход FFmpeg, кэш по файлу и настройкам. Кадры пронумерованы по порядку;
приблизительное время — в `storyboard.json`. Для непонятного перехода извлеки
короткий интервал, например `--start 3 --duration 2 --frames 12` в другую папку.
Для визуального разбора открывай изображения инструментом просмотра файлов.

Превью может показывать только хиро. Не называй его анализом всей страницы.
Проверь секции из `sections.json`; если ролик не содержит все основные секции,
запиши прокрутку оригинального сайта до футера:

```text
node scripts/capture_site.cjs https://example.com .cache/<slug>/live-ref
```

Открой обзор и проверь `capture.json`: `covered_to_footer` должен быть `true`.
Бюджет по умолчанию — 120 шагов с перекрытием экранов; при достижении лимита
скрипт возвращает ошибку, а не выдаёт неполную съёмку за полную. Для длинной
страницы увеличь `--max-steps`. У бесконечного скролла, вложенного контейнера,
cookie-окна или недоступного сайта опиши границы фактического просмотра.
Отдельно проверь значимые hover/click/drag, меню и скрытые вкладки в браузере:
прокрутка не раскрывает все интерактивные состояния.

Выгрузи токены главного референса через
`node .claude/skills/site-from-ref/fetch_style.js <id> .cache/<slug>/style`.
Проверь наличие и содержание всех четырёх файлов; при сетевом сбое укажи, что
не получено. Не придумывай значения и не выдавай отсутствующие токены за извлечённые.

## Анимации по всей странице, без дублей направлений

```text
python3 scripts/select_references.py motion "появление текст scroll hover" --out .cache/<slug>/motion.json
```

Поиск выдаёт **один результат на смысловой паттерн** из `pattern_catalog.json`,
а не 1944 почти одинаковых карточки. Направление, скорость, easing, библиотека
и триггер — настройки/варианты; появление слева, справа, сверху и снизу не
считай четырьмя разными паттернами. Выбирай вариант внутри подходящей группы.
Проверь и другие группы под концепцию, а не только первые результаты поиска.

Насыщай движением все подходящие части страницы: хиро, типографику, появление
секций, изображения, навигацию, кнопки, карточки, числа, финальный CTA и футер.
Ориентир для длинного лендинга — 6–10 совместимых паттернов и повторяемые
микровзаимодействия; это не квота. Добавляй больше там, где они помогают теме,
а не несколько конкурирующих WebGL-фонов или один reveal под разными именами.
Плотность адаптируй к брифу: спокойному финансовому сайту нужны другие эффекты,
чем музыкальному фестивалю. Объясни пропущенные семейства, если они мешают концепции.

Перед переносом прочитай оригинальный CSS/компонент и посмотри локальное демо
или видео. Нет исходника/видео — `python3 scripts/fetch_assets.py --motion <example-id>`.
React Bits загружается с сайта автора отдельно; компоненты не распространяются
в этом репозитории. Codrops: исходный снимок может лежать в ZIP; свежий архив
скачивается в `motion_reference/upstream/`, путь указан в отчёте загрузки.
Не заменяй лицензии/происхождение предположениями. Нет проверенной лицензии —
используй пример как визуальный референс или выбери вариант с ясными условиями.
Если медиа автора изменилось и хеш не совпал, проверь URL/тип содержимого и при
необходимости повтори с `--allow-updated`; отметь использование обновлённого
материала из отчёта. Код по этому флагу не обновляется. Не скрывай сетевые ошибки.

Переноси выбранный приём под стек результата. Для самостоятельного HTML адаптируй
механизм в CSS/JS; React-компоненты не вставляй без среды выполнения. Сохрани
полные применимые лицензии и attribution в `THIRD-PARTY-NOTICES.txt` рядом с сайтом.
React Bits разрешает использование внутри сайта, но запрещает распространение
самих компонентов отдельно/в сборниках; прочитай загруженную лицензию.

## План реализации и проверка

Создай `generated-sites/<slug>/motion-plan.json` до QA. Пример структуры:

```json
{
  "language_selectors": {"en": "[data-set-lang='en']", "ru": "[data-set-lang='ru']"},
  "pause_selector": "#pause-motion",
  "content_selectors": ["h1", "main", "footer"],
  "effects": [
    {"pattern_id": "pattern.content.enter", "example_id": "animista.fade-in", "selector": ".section-copy", "trigger": "scroll", "property": "opacity", "loop": false},
    {"pattern_id": "pattern.motion.rotate", "example_id": "animista.rotate-center", "selector": ".orbit", "trigger": "autoplay", "property": "transform", "loop": true}
  ]
}
```

В реальном плане укажи все эффекты, действительные селекторы/ID и источник,
место применения, адаптацию и reduced-motion поведение. Выбери измеряемое
свойство (`opacity`, `transform`, `background-position`, и т. п.); для canvas/
шейдеров добавь отдельную проверку изображения во времени. Обновляй план при
замене эффекта, не оставляй фиктивные записи из примера.

Контент виден без JS; JS добавляет движение после успешной инициализации.
Слушай изменение `prefers-reduced-motion` во время работы, отключай CSS/WAAPI,
rAF/WebGL и smooth scroll. Вынеси циклы на паузу по кнопке и вне экрана/скрытой
вкладки. Не оставляй длинный текст мерцающим и не блокируй чтение прелоадером.

```text
node scripts/qa_motion.cjs generated-sites/<slug>/index.html generated-sites/<slug>/motion-plan.json .cache/<slug>/qa
node scripts/capture_site.cjs generated-sites/<slug>/index.html .cache/<slug>/final
```

Открой EN/RU-скриншоты и финальный обзор, исправь перекрытия. Автопроверка меряет
реальное изменение свойств после триггера, паузу, начальный/динамический reduced
motion, отсутствие overflow, ошибки JS и видимость основного текста без JS.
Если эффект не укладывается в измерение CSS-свойства, дополни проверку браузером
и запиши конкретное наблюдение, а не обходи неуспешный тест.

Зарегистрируй результат в `projects.json` по исходному процессу и пересобери
`python3 build_generated.py`. Подними сервер, если он не работает. Сообщи ссылку
на сайт, выбранные референсы, число уникальных паттернов и итоги проверок,
включая недоступные источники. Этот скилл не запускает сравнение, публикацию,
GitHub push или рассылку без соответствующего запроса пользователя.
